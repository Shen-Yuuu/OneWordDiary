# 一字日记：文字长卷与单日详情设计

- 日期：2026-08-18
- 范围：实施节点 3，HarmonyOS 手机端
- 需求来源：产品方案与 `docs/design/oneword-ui-page-state-list.md`

## 方案

文字长卷采用日期游标分页，每次按 `local_date` 倒序读取 30 条记录。页面使用 `List`、`LazyForEach` 和稳定日期 key，只构建当前可见范围附近的节点，满足长期积累 365 条以上记录时的滚动要求。

不采用一次读取全部记录，避免记录增长后产生不必要的内存和组件压力；也不按月份单独请求，因为 1.0 不提供日历浏览，逐月查询会增加跨月加载状态而没有明确收益。

## 数据与状态

`DiaryRepository` 增加“指定日期之前、限制数量”的查询能力；第一页不传日期游标，后续页使用当前最后一条记录的 `local_date` 作为排他游标。查询结果始终按日期倒序返回。

`ScrollViewModel` 管理空状态、首次加载、追加加载、加载失败和是否还有下一页。每条记录转换成统一的长卷展示项，预先计算月份标题、日期、星期、左右错落位置和保存时的风格标识，UI 不负责日期规则。

`DetailViewModel` 只接收 `localDate`，再通过服务重新读取记录。这样详情能够正确表达记录不存在、读取失败、正文和正式留白四类状态，而不会依赖导航时传递的过期对象。

## 页面与导航

- 首页继续作为唯一 `Navigation` 根页面。
- 点击“长卷”压入文字长卷 `NavDestination`。
- 点击长卷节点压入单日详情 `NavDestination`，只传日期参数。
- 返回详情时保留已加载记录和长卷滚动位置；返回首页后今日页按现有逻辑重新恢复。
- 长卷顶部提供返回和“最近七日”分享占位入口，分享能力仍在节点 5 实现。

长卷使用连续中轴线、月份分段和左右错落节点。`WORD` 显示 1–4 字正文；`BLANK` 使用淡圆圈并明确朗读为正式留白。缺失日期不生成节点。参考稿中的注解摘要不进入长卷，因为产品方案明确要求注解只在单日详情显示。

详情完全只读，展示日期、正文或留白、可选注解和记录保存时的字体/纸张风格。节点 3 不提供历史编辑、单条删除或实际分享。

## 错误与性能

- 首次查询失败显示克制错误页和重试。
- 追加失败保留已加载内容，在列表末尾提供重试。
- 重复触发触底加载时只允许一个请求进行。
- 页内追加按日期去重，导入或异常数据不能生成重复节点。
- 详情查询不到记录时显示“这一天没有记录”，不把正式留白误判为空数据。

## 验证

- Repository 测试覆盖游标排他、倒序、页大小和无重复分页。
- ViewModel 测试覆盖空长卷、月份分段、正文/留白节点、追加、失败恢复和详情四类状态。
- 本地 Hypium 测试通过后执行 Debug HAP 构建。
- 真机阶段验证 365 条以上滚动、返回位置、屏幕朗读、大字号和不同手机宽度。
