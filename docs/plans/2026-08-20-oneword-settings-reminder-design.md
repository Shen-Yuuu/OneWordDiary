# 一字日记：节点 4 设置、风格与本地提醒设计

- 日期：2026-08-20
- 状态：已实现，待真机验收代理提醒
- 适用范围：HarmonyOS 手机端 1.0

## 1. 已确认的产品行为

- 设置页延续现有暖纸、留白和较大辅助字号，不重新建立一套视觉语言。
- 1.0 只有 `paper_ink`（纸墨）和 `plain_ash`（素灰）两套完整预设。
- 风格切换影响当前输入预览和未来记录；历史记录继续使用保存时的 `font_id` 与 `paper_id`。
- 每日提醒采用固定循环提醒。即使当天已经完成记录，到达设定时间仍会显示。
- 提醒使用温和回望语义，正文不包含日记内容。
- 备份与恢复属于节点 6，节点 4 不提供虚假可用入口。

## 2. 设置页

设置页使用 `Navigation` / `NavDestination`，包含：

1. 纸墨、素灰风格卡片。
2. 每日提醒开关和时间选择。
3. 隐私说明入口。
4. 清空全部数据入口。

设置读取失败显示可重试状态。单项保存失败时恢复原值并显示简短提示，不让界面与持久化状态分离。首页在设置页返回后重新加载设置，使输入预览立即使用新风格。

## 3. 每日提醒

- 默认关闭，默认时间为 `21:00`。
- 未由用户主动开启时不申请通知权限。
- 首次开启先显示用途说明，用户继续后再调用系统通知授权。
- 使用 `reminderAgentManager` 发布星期一至星期日循环的 `ReminderRequestAlarm`，由系统在应用退出后托管。
- 通知标题使用“一字”，内容使用“留一点时间，回望今天。”，不读取或拼接任何日记字段。
- 保存系统返回的提醒 ID，用于修改、关闭和状态核对。
- 修改时间采用“先发布新提醒，成功后取消旧提醒并保存新配置”的顺序；发布失败时保留旧提醒与旧时间。
- 关闭提醒时取消现有提醒，成功后再保存关闭状态。
- 权限拒绝后保持关闭并记录已请求状态；后续不反复弹系统授权框，改为提供系统设置入口。
- 应用启动和回到前台时核对系统通知开关及有效提醒。系统关闭通知、提醒丢失或配置不一致时，设置页显示真实状态并允许修复。
- Previewer 只验证 UI；通知授权、后台触发、系统设置返回、重启及时区变化使用真机验收。

## 4. 清空全部数据

清空采用两个确认层：

1. 第一次说明会删除全部日记和设置。
2. 第二次明确数据无法恢复，并使用危险操作样式。

跨 RDB、Preferences 和系统提醒无法使用同一个数据库事务，因此使用持久化清空标记保证最终一致：

1. 写入 `reset_pending = true`。
2. 取消应用的全部代理提醒。
3. 在 RDB 事务内清空日记。
4. 重置 Preferences，使清空标记与其他设置一起移除。

如果中途失败或进程退出，下次初始化检测到 `reset_pending` 后继续完成已经由用户确认的清空操作。清空成功后回到首页首次使用状态：无记录、纸墨风格、提醒关闭、默认时间 `21:00`。

## 5. 隐私说明

隐私页面只保留与 1.0 实际行为有关的内容：

- 日记默认仅保存在本机。
- 无账号、无网络请求、无统计和广告 SDK。
- 提醒不包含日记正文或注解。
- 分享默认不包含注解。
- 系统自动备份关闭。
- 节点 6 的备份只能由用户主动导出或导入。

## 6. 代码边界

- `SettingsViewModel`：设置页状态、保存回滚、提醒操作和清空状态。
- `ReminderScheduler`：封装通知权限、代理提醒发布/取消/核对和系统设置入口。
- `AppResetService`：清空顺序、持久化标记和启动恢复。
- `SettingsRepository`：保存提醒 ID、授权已请求状态与清空标记。
- `SettingsPage` / `PrivacyPage`：只负责展示状态和转发用户操作。

页面不直接调用 Preferences、RDB 或系统通知 API。

## 7. 验收

- 风格切换保存失败会回滚；历史记录风格不变化。
- 未主动开启提醒时不申请权限。
- 权限允许后创建每日循环提醒；修改时间和关闭提醒不会残留重复任务。
- 权限拒绝或系统关闭通知时不崩溃、不反复弹窗，设置页能解释并提供修复入口。
- 清空成功后记录、设置和提醒都恢复为首次使用状态。
- 清空被中断后可在下次启动继续，不出现部分日记残留。
- 单元测试覆盖设置、提醒和清空状态；Debug HAP 构建通过。

- 清空使用 `reset_pending` 恢复标记；提醒发布失败保留用户开启意图，可在设置页重试。
- 39 个本地单元测试全部通过，Debug `assembleHap` 构建通过。
