# 一字日记：真机 UI 反馈修复设计

- 日期：2026-08-20
- 范围：节点 3.5 视觉验收补丁，先于节点 4
- 依据：2026-08-20 首页完成态、文字长卷、单日详情真机截图

## 问题与判断

- 文字长卷能够显示记录正文，说明记录已正确写入 RDB；首页完成态与详情正文缺失属于共享展示布局问题，不修改数据模型与保存规则。
- 首页完成态和详情都在无显式内容高度的 `Stack` 中叠放正文与“已”印章。真机渲染表明该结构存在测量或裁切风险，应改为尺寸确定的纵向布局，印章使用独立行定位。
- 日期、说明、按钮、长卷节点等辅助文字主要为 10–12fp，在当前手机密度下偏小。
- 备注入口仅使用落字按钮旁的图标，发现性和“随正文一起保存”的语义不足。

## 采用方案

1. 首页完成态和详情页移除正文区域的叠层依赖，改成“印章行 → 正文/留白 → 意境文案 → 日期/备注”的确定性纵向布局。
2. 今日编辑页始终展示“备注（可选）”单行输入区；正文与备注继续使用同一次确认和同一事务保存，不新增步骤。
3. 正文限制仍为 1–4 grapheme，备注仍为最多 30 grapheme 且不允许换行；正式留白继续清空正文与备注。
4. 辅助文字、按钮和长卷日期整体增加约 2fp；长卷正文按字数适度增大，首页与详情的主字仍保持强焦点。
5. 不修改 Repository、RDB schema、DiaryService、修订次数与截止时间规则。

## 重复测试

- 开发阶段可通过系统“清除应用数据”或卸载重装重置应用沙箱。
- 不通过修改系统日期反复测试，以免干扰修订截止时间逻辑。
- 节点 4 完成后使用应用内“两步确认 → 清空全部数据”作为主要人工回归入口。

## 验证

- 覆盖 1、2、3、4 字正文以及带/不带备注的首次提交、完成态、长卷和详情。
- 确认首页和详情均显示正文，详情显示备注，长卷仍不显示备注。
- 运行全部 32 个本地测试并构建 Debug HAP。
- 再次获取首页完成态、长卷、详情真机截图进行视觉验收。

## 实现结果（2026-08-20）

- 首页完成态与详情改为显式正文高度和独立印章行。
- 备注始终显示；留白确认会提示已填写备注不会保存。
- 辅助文字与长卷正文整体增加约 2fp。
- 新增 2 个正文/备注规则测试，全项目 32 个本地测试通过，Debug HAP 构建成功。
