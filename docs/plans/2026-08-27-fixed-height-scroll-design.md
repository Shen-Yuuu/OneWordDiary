# 长卷固定高度与节点轴线修复设计

## 问题

当前源码虽然为长卷记录设置了固定高度，但记录内部仍使用百分比高度和弹性权重。`ListItem` 自动测量时，子组件的百分比高度参与反向约束，导致单条记录被拉伸到接近整个列表可视区。中轴节点与完整竖线共处于不稳定的 Stack 测量区域，因此出现竖线存在而圆形节点消失的问题。

## 目标

- 手机页面一屏展示约 4–6 条记录。
- 普通记录、含备注记录和缺失日期均有确定高度，不随列表剩余空间伸长。
- 文字、正式留白和缺失日期的圆形节点始终可见。
- 文字长卷与最近七日分享继续使用同一套节点组件。

## 布局方案

采用固定高度叶子布局，不再让记录内部使用 `height('100%')` 或 `layoutWeight` 参与纵向测量。

- 月份标题：48vp。
- 普通记录：104vp。
- 含备注记录：128vp。
- 缺失日期：56vp。
- `ListItem` 内增加与记录总高度一致的明确高度容器。
- 正文左右区域使用确定的半屏宽度和节点高度，不使用弹性高度。

中轴不再用一根贯穿节点的 Divider，也不使用 Stack 覆盖层。正文、轴线和另一侧留白组成同一个实体 Row；独立的 ScrollAxisNode 组件由上半段竖线、固定节点容器和下半段竖线组成：

- 文字记录：12vp 朱砂色实心圆。
- 正式留白：24vp 朱砂色空心圆，中心保留小点。
- 缺失日期：14vp 淡灰色空心圆。
- 所有节点使用 32vp 的原生 SVG 资源并通过 Image 渲染，避免空布局组件、符号字体或嵌套 Builder 在模拟器中被优化掉。

## 共享与验证

`ScrollRecordNode` 继续作为文字长卷与七日分享的共享组件，`ScrollLayoutMetrics` 负责两处共同使用的尺寸。七日分享卡片高度继续根据同一组记录高度求和。

验证内容：

- 单条记录不再占满列表剩余高度，一屏约出现 4–6 条。
- 文字、留白、缺失三类节点均位于中轴线上并保持可见。
- 最近七日分享与长卷使用相同间距和节点。
- 执行 HAP 构建与 ArkTS 单元测试；模拟器在线时安装并检查实际页面。
