# 节点 6–7：基础备份、恢复与整体验收

## 范围

节点 6 实现 `.oneword` 文件导出和导入；节点 7 补齐自动化测试、权限与隐私审计、构建和缺陷记录。1.0 的备份不加密，不包含提醒权限、提醒时间、设备信息或隐藏标识。

节点 5 当前只保留本地预览与数据模型；在用户另行明确授权前，不把包含日记正文的图片交给系统分享面板，节点 7 将此项记录为待确认。

## 文件格式

- UTF-8 JSON，扩展名 `.oneword`，顶层 `format_version` 固定为 `1`。
- 包含导出时间、当前风格和日记记录。
- 日记字段完整保留：本地日期、正文、备注、记录类型、历史字体与纸张、提交和修订时间、时区偏移、修订状态、数据版本。
- 不包含提醒配置、通知权限、日志或统计字段。
- 导入上限为 5 MiB、10000 条记录；这覆盖约 27 年的一日一记，同时避免异常文件占用过多内存。

## 导出流程

设置页进入“备份与恢复”，先说明文件未加密且包含私人记录。用户确认后调用系统文件保存选择器，由用户决定位置和文件名；在选择完成前不生成外部文件。取消选择视为正常返回，不显示错误。

导出服务从 RDB 读取全部记录和当前风格，通过纯 `BackupCodec` 生成格式稳定的 JSON，再写入系统返回的 URI。写入失败不改变数据库与设置。

## 导入流程

系统文件选择器只选择一个 `.oneword` 文件。读取后先在内存中完成全部预检：文件大小、JSON 结构、版本、字段类型、日期真实性、记录数量、日期唯一性、正文与备注 grapheme 规则、枚举、时间字段与风格标识。

预检通过后先展示导入数、冲突跳过数和风格处理结果，用户再次确认才写入。冲突日期始终保留本机记录，所有缺失日期在同一 RDB 事务中写入；中途异常整体回滚。

风格合并规则：本机导入前没有任何日记时恢复备份风格；本机已有日记时保留当前风格。提醒配置始终保留本机状态。

## 架构

- `BackupCodec`：纯数据编码、解析、全量校验与导入计划计算，便于单元测试。
- `BackupService`：协调 Repository、设置、文件 URI 与事务，不包含 UI。
- `BackupViewModel`：管理说明、选择中、预检结果、确认、执行结果和错误状态。
- `BackupPage`：只负责用户确认和调用系统文件选择器。
- Repository 增加完整读取和“只插入缺失日期”的事务能力，不改变既有提交与修订规则。

## 错误与隐私

- 页面只显示可理解错误，不展示路径、正文、备注或异常堆栈。
- 日志只记录事件名和错误类别，不记录文件内容。
- 损坏、未知版本、重复日期、非法字段或超限文件在事务前失败。
- 导出与导入均由用户主动操作；取消选择器不会留下半成品或修改数据。

## 节点 7 验收

- 增加 codec、导入合并、事务回滚、损坏文件和上限测试。
- 运行现有领域测试与 Debug HAP 构建。
- 检查权限、自动备份配置、依赖、日志、缓存、网络能力和开发素材。
- 将无法在 Previewer 完成的真机项目明确列为待验收，不用“已实现”替代“已验收”。
- 输出一份简短验收记录，只包含通过项、待真机项和实际缺陷。
