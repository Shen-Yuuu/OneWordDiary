# 分享备注与不透明图片导出设计

## 目标

修复单日和最近七日分享开启“展示备注”后备注文字仍不出现的问题，并确保导出的 PNG 自身具有不透明背景，不再依赖接收应用如何解释透明通道。

## 备注显示

当前界面用 `showNote` 布尔值控制子组件是否创建备注区域。开关状态已经变化，但子组件中的条件内容没有可靠刷新。新实现改为由“最终要显示的备注文本”直接驱动界面：

- 开关关闭或日期缺失：传入空字符串，不创建备注区域。
- 开关开启且有备注：传入真实备注。
- 开关开启但记录没有备注：传入“这条记录没有备注”。

单日分享、最近七日分享和文字长卷节点统一依据最终文本是否为空计算备注区域及节点高度。页面仍保留显式开启/关闭分支和渲染修订号，确保 ArkUI 替换分享卡片子树。

## 不透明图片导出

组件快照仍以高分辨率 PixelMap 生成。写入 PNG 前增加一个像素合成步骤：

1. 读取快照的尺寸、行跨度、像素格式和 Alpha 类型。
2. 将每个像素与当前主页纸张底色进行 Alpha 合成。
3. 输出 RGBA_8888、AlphaType.OPAQUE 的新 PixelMap。
4. 仅把不透明 PixelMap 编码为 PNG 并交给系统分享。

纸墨风使用主页背景色 `#FDF8F7`，素灰风使用 `#F7F7F5`。这能保证导出文件本身不透明，而不只是预览界面看起来有底色。

## 后续用户背景图片

该方案兼容未来的用户自定义背景：背景图片作为分享卡片的底层内容参与组件快照；像素合成只用主页纸张色填补背景图未覆盖或仍透明的区域。将来只需新增背景来源和图片加载状态，无需改动分享协议或 PNG 导出流程。

使用纯色图片资源也可以实现当前需求，但会增加资源、解码和缩放成本，因此当前不引入一张内容完全相同的背景图。

## 错误处理

- 仅支持组件快照常用的 RGBA_8888 和 BGRA_8888；遇到其他像素格式时中止分享并沿用现有“分享图未能生成，请重试”提示，避免生成颜色错误的图片。
- 原始和合成后的 PixelMap、文件句柄及 ImagePacker 都在异常路径释放。

## 验证

- 单日和最近七日的备注开关均能反复切换，并显示真实备注或无备注提示。
- 缺失日期不增加备注区域，时间线节点和卷尾不重叠。
- 纸墨风与素灰风导出的 PNG 所有像素 Alpha 均为 255。
- 导出的图片在未点开时显示正常底色，点开后内容与预览一致。
- ArkTS 本地测试和 Debug HAP 构建通过。
