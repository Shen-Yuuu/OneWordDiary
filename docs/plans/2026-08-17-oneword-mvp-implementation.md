# 一字日记：1.0 实施计划

- 日期：2026-08-17
- 对应方案：[2026-08-14-oneword-mvp-design.md](./2026-08-14-oneword-mvp-design.md)
- 工程目录：`OneWord_dev/`
- 基线：HarmonyOS 6.0.1 / API 21 / Stage 模型 / 手机
- 状态：节点 4 的代码、本地单元测试与 Debug 构建已完成；代理提醒及节点 1–4 的真机恢复、性能与无障碍验收在获得测试设备和代理提醒开放能力后补做

## 1. 实施目标

交付一个完全离线、可在 HarmonyOS 手机上运行的 1.0：

- 用户可以写下 1–4 个用户感知字符或选择留白。
- 首次提交后，在固定截止时间前只有一次修订机会。
- 用户可以回看文字长卷和单日详情。
- 用户可以设置本地提醒、生成单日/7 日分享图。
- 用户可以主动导出和安全导入基础备份。
- 应用不联网、不统计、不自动备份私人数据。

预计单人开发为 **14–19 个工作日**；种子验证另需至少 7 个自然日。估算包含开发素材，不包含最终商用字体、图标制作和商店审核等待。

## 2. 当前工程状态

`OneWord_dev/` 已是可用的 HarmonyOS Stage 模板，不需要重新建项目。

已确认配置：

- `targetSdkVersion`：`6.0.1(21)`
- `compatibleSdkVersion`：`6.0.1(21)`
- `deviceTypes`：仅 `phone`
- `bundleName`：模板值 `com.example.oneword`
- 首页：今日记录闭环，并已接入文字长卷与单日详情
- 测试：Hypium 本地测试已覆盖领域规则、今日状态、游标分页、文字长卷与详情，共 30 个用例
- 签名：尚未配置，不影响本地开发
- 系统备份：模板默认存在 `EntryBackupAbility`，且 `allowToBackupRestore=true`

开始业务开发时，将开发期 `bundleName` 改为 `com.oneword.diary`，应用显示名改为“一字日记 / OneWord Diary”。首次外部分发前必须确认最终 `bundleName` 可用，因为上架后不能更换。

### 节点 1：领域规则与本地数据

预计：2–3 天。后续所有页面依赖本节点。

工作：

- 定义 `DailyRecord`、`RecordType`、`StylePreset`、`ReminderSettings` 等严格类型。
- 实现 grapheme 规范化、计数和输入校验。
- 提供可替换的 `Clock`，业务代码不能直接散落调用系统当前时间。
- 实现本地日期、时区 offset 和 `revision_deadline_at` 计算。
- 创建 RDB、`daily_record` 表、唯一主键和 schema 迁移入口。
- 创建 `DiaryRepository`、`SettingsRepository`。
- 创建 `DiaryService`，封装首次提交、留白、修订、查询资格和清空规则。
- 首次提交和修订都放在事务中，处理快速重复调用。

完成条件：

- Emoji、ZWJ、肤色修饰、组合字符和中文输入的测试通过。
- 23:58、23:59、跨日、时区变化和时间回拨场景有固定时钟测试。
- 同一日期并发提交只生成一条记录。
- 修订写入失败或取消时不消耗次数。
- 进程重启后可以完全从 RDB 恢复状态。
实现结果（2026-08-18）：

- 已建立 `DailyRecord`、留白/写字类型、设置、错误、时钟和本地日期模型。
- 已实现 NFC 规范化与用户感知字符计数，覆盖中文、组合字符、肤色修饰、旗帜和 ZWJ Emoji。
- 已建立 `daily_record` RDB 表、日期主键、版本迁移入口、RDB/内存仓储和 Preferences 设置仓储。
- 已实现首次提交、正式留白、同日防并发、截止时间判断和仅一次修订；事务失败不会写入 `revision_used`。
- 服务在 `EntryAbility` 加载页面前初始化，页面层后续只通过服务访问数据。
- `hvigorw test` 与 Debug `assembleHap` 均通过；本地测试已实际执行并生成覆盖率报告。
- 尚未声称完成真机 RDB 重启恢复验证：这项需要可运行的 API 21 模拟器或真机，最迟在节点 7 整体验收前补做，不阻塞节点 2 页面开发。

工作：

- 构建唯一首页和今日状态 ViewModel。
- 完成日期、灵感、正文输入、字符反馈、始终可见的可选备注和风格预览。
- 完成“落字 → 确认 → 收入长卷”的双确认流程。
- 完成“把今天留给空白”流程。
- 完成已提交卡片、剩余修订提示和永久定稿流程。
- 增加写入中禁用、防重复触发、失败反馈和进程恢复。
- 实现短定格动效、轻触反馈以及减少动效替代方案。

完成条件：

- 冷启动到提交不超过 3 次主要点击。
- 写字、留白、写字转留白、留白转写字均通过。
- 退出确认页、切后台和杀进程不会误提交或误消耗修订。
- 大字号和屏幕朗读可完成全部流程。

实现结果（2026-08-18）：

- 已以 `TodayUiState` 与 `TodayViewModel` 实现未记录、编辑、双确认、写入中、错误、已记录、一次修订和永久定稿状态。
- 已拆分日期栏、灵感、编辑器、确认层、完成卡片和启动错误组件；长卷、设置和分享保留可辨识入口但不提前实现后续节点。
- 已实现正文/注解就近校验、正式留白、取消不落库、保存失败重试、累计天数与冷启动按 RDB 恢复。
- 已提交内容在今日完成卡片中隐藏注解；注解只留给节点 3 的单日详情，符合隐私规则。
- 成功持久化后触发柔和系统触感；设备不支持振动时静默降级，不改变保存结果。页面动效仅使用 240ms 以内的无位移淡变。
- 新增 8 个 ViewModel 状态测试；`hvigorw test` 与 Debug `assembleHap` 均通过，ViewModel 行覆盖率约 70.9%。
- 尚待 API 21 真机验证中文输入法、返回/切后台/杀进程、实际触感、大字号与屏幕朗读，因此本节点标记为“已实现”而非“已验收”。

### 节点 3：文字长卷与详情

预计：1.5–2 天。

工作：

- 按日期倒序读取记录，使用虚拟化列表和稳定 key。
- 构建月份分段、正文节点、留白节点和空状态。
- 点击节点进入单日详情。
- 详情展示日期、正文或留白、注解和提交风格。
- 显示“已留下 N 天”，写字与留白都计入。
- 为未来分页和月份查询保留 Repository 接口，但 1.0 不增加日历模式。

完成条件：

- 365 条以上记录滚动稳定，无明显卡顿或组件爆量。
- 历史记录不随当前风格切换而改变。
- 缺失记录和正式留白在 UI 与朗读语义上明确不同。


实现结果（2026-08-18）：

- 已实现排他日期游标分页，RDB 与内存仓储均按 `local_date` 倒序每页读取 30 条，并对追加结果按日期去重。
- 已实现 `List` + `LazyForEach` 长卷，使用日期稳定 key、月份分段、正文左右错落和正式留白中轴节点；长卷不展示注解。
- 长卷与详情均按记录保存时的字体和纸张预设显示，正文 1–4 字使用自适应字号；顶部展示累计记录天数。
- 已通过 `Navigation` / `NavDestination` 接入长卷和只读单日详情；详情重新按日期查询并覆盖正文、留白、不存在和读取失败状态。
- 新增 8 个节点 3 测试，全项目共 30 个测试；`hvigorw test` 与 Debug `assembleHap` 均通过，整体行覆盖率 63.75%，ViewModel 行覆盖率 79.10%。
- 尚待 API 21 真机或模拟器验证 365 条以上长卷滚动、返回位置、大字号、屏幕朗读和不同手机宽度，因此本节点标记为“已实现”而非“已验收”。

### 节点 4：设置、风格与本地提醒

预计：1.5–2 天。

工作：

- 提供 `paper_ink` 和 `plain_ash` 两套完整预设。
- 风格切换只影响新记录和当前预览。
- 提供提醒开关和时间选择。

- 处理拒绝、系统关闭、调度失败、修改时间、关闭提醒和设备重启。
- 提供隐私说明入口和“清空全部数据”两步确认。

完成条件：

- 未主动开启提醒时不申请通知权限。
- 权限拒绝不会反复弹窗，设置页有解释和系统入口。
- 清空失败时不留下半清空状态；成功后回到首次使用状态。

实现结果（2026-08-21）：

- 已完成设置页、隐私说明页、纸墨/素灰切换、通知权限按需申请、每日循环提醒及提醒状态核对。

- 真机验收需覆盖：首次授权、拒绝后重试、后台与退出后触发、系统关闭通知后恢复、改时无重复、重启及时区变化，以及清空后的提醒取消。

### 节点 5：分享图片

预计：2 天。

工作：

- 实现独立 `ShareCardRenderer`，不从页面截图拼接。
- 支持单日卡和最近 7 日微型长卷。
- 两类分享图默认都不包含注解。
- 提供固定分享预览，确认后调用系统分享面板。
- 适配两套风格、不同密度和大字号。
- 临时图片写入应用缓存，完成或超时后清理。

完成条件：

- 分享图与预览一致，不截断、不拉伸。
- 不包含隐藏标识、日记注解或分析数据。
- 分享取消、目标应用失败或存储异常不影响原始日记。
- 缓存中没有长期遗留的分享图片。

### 节点 6：基础备份与恢复

预计：2 天。

工作：

- 定义 `.oneword` 格式和 `format_version=1`。
- 导出记录和风格设置，不导出设备通知权限。
- 导出前提示文件未加密且包含私人记录。
- 通过系统文件选择能力让用户主动决定位置。
- 导入时先解析到内存模型并完成全量预检。
- 冲突日期保留本机记录，只导入缺失日期。
- 所有导入写入在同一事务中完成。
- 完成后报告导入数、跳过冲突数和错误原因。

完成条件：

- 损坏 JSON、未知版本、非法日期、超长字符和重复记录都不能改变本机数据。
- 中途失败时事务回滚。
- 导出再导入可还原记录内容、时间字段和历史风格。
- 大文件有数量或大小上限，不造成明显卡死或内存失控。

## 6. 执行约束

- 产品方案是需求唯一来源；发现冲突时先修订方案，再改代码。
- 每个节点完成后先运行相关测试，再进入依赖它的下一个节点。
- 不提前实现后续版本能力。
- 不为 1.0 拆分多模块、引入通用框架或搭建网络层。
- 任何可能导致日记丢失的操作都必须有事务、预检或可恢复路径。
- 用户正文和注解不得进入日志、崩溃信息、分享元数据或测试夹具。
