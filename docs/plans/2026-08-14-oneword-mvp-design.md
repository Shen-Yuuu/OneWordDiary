# OneWord 一字日记：MVP 产品与技术设计

日期：2026-08-14  
状态：已确认，待开发

## 1. 产品定义

**一天一字，一年一诗。**

OneWord 是一款离线优先的 HarmonyOS 原生日记工具。它让用户每天用 1–4 个字符记录当下，以时间沉淀为私人文字长卷。产品不以连续打卡、社交比较或信息流占据用户注意力，而以留白、克制和可回看的积累建立习惯。

目标用户是 18–35 岁、偏好极简生活和有审美表达需求的用户。首版的核心验证目标是：用户在第 7 天仍愿意打开并记录，而不是堆叠功能数量。

## 2. 已确认的产品决策

- 首发采用“**一字仪式**”路线，而非情绪轻日记或社交报告路线。
- 数据仅保存在本机；首发不登录、不云同步、不接入统计 SDK、不发起网络请求。
- 单日可输入 1–4 个用户感知字符；可选一条不超过 30 字的注解。
- 用户可以选择“留白”；留白是平等的最终状态，不等于未完成或失败。
- 首次提交后，当地时间 23:59 前可以修改一次；修订后永久定稿。
- 唯一一次修订允许“已写 → 留白”和“留白 → 已写”。
- AI 组诗、情绪标签、成就、月年统计、登录、云同步和多浏览模式不进入 1.0。

## 3. 批判性问题与解决方案

| 产品矛盾 | 风险 | 解决方案 |
| --- | --- | --- |
| 每天一字太严格 | 用户偶有表达欲，可能放弃使用 | 放宽到 1–4 字符，但产品语言仍称“一字” |
| 提交立即锁死 | 错字与误触制造挫败感 | 当天仅有一次修订；修订确认后永久定稿 |
| 每天必须记录 | 打卡焦虑违背轻盈感 | 留白成为正式状态，不计算连续天数 |
| 主题、字体过多 | 选择疲劳，破坏极简 | 1.0 仅提供两套风格，其余后置到高级版 |
| 统计和成就过早出现 | 产品退化为压力型打卡工具 | 仅显示温和的“已记录 N 天”，不做排行榜与连胜 |
| AI 组诗与本地隐私冲突 | 用户不清楚日记是否上传 | 2.0 才引入，必须逐次授权、明确联网与最小数据范围 |
| 严格离线却要衡量留存 | 无法取得 D7、分享率等遥测 | 依靠商店反馈、主动反馈邮箱和种子用户访谈；不能暗接分析 SDK |

## 4. 1.0 功能范围

### 包含

1. 今日记录：日期、每日灵感、1–4 字输入、字体预览、可选注解和二次确认。
2. 今日留白：用户可直接确认“把今天留给空白”。
3. 一次修订：提交后显示剩余一次机会；第二次确认后不再提供编辑入口。
4. 文字长卷：按日期纵向浏览字、日期和留白；点击查看单日卡片。
5. 本地提醒：用户主动开启并选择时间。
6. 本地分享：导出单日卡片或最近 7 日微型长卷，由系统分享面板分发。
7. 基础设置：两套字体/纸张风格、提醒开关、隐私说明。

### 明确不包含

登录、社区、云同步、情绪标签、成就、月度/年度统计、AI 组诗、隐私锁、桌面卡片、日历/卡片浏览模式。

## 5. 信息架构与交互

```text
今日（默认首页）
├─ 输入 / 留白 / 提交
├─ 当日完整卡片
├─ 文字长卷
├─ 分享预览
└─ 设置（提醒、主题、数据）
```

首页是唯一主入口，不设多栏底部导航。长卷与设置置于右上角，用户每次打开都直接面对“今天”。

### 今日记录流程

1. 显示日期与一行低对比度灵感；灵感可换一条，不保存、不强迫回应。
2. 用户输入后实时查看艺术字体预览；“添加一句注解”默认折叠。
3. 点击“落字”进入确认页；再次点击“收入长卷”才写入数据。
4. 以 180–300ms 的纸张/墨迹定格动效和轻触感反馈完成提交。
5. 提交后显示“今日尚可修订 1 次，至 23:59”。修订前展示原内容与永久定稿提示。

留白也采用确认页，文案为“把今天留给空白”。长卷中使用淡圆圈表示，日期位置完整保留。

### 视觉原则

- 暖白宣纸、墨灰文字与极淡朱砂色状态点。
- 仅在落字、长卷展开、图片导出时使用动效；遵循系统“减少动效”偏好。
- 首页用日期、纸张肌理与每日灵感缓解空白感，但不加入天气、名言流、待办等噪声。

## 6. 技术架构

采用 ArkTS、ArkUI 声明式 UI 与 Stage 模型。所有代码保持严格类型；界面状态使用不可变更新；复杂 UI 抽为可复用组件。

```text
ArkUI 页面 / 可复用组件
        ↓
Today / Scroll / Settings ViewModel
        ↓
DiaryService（日期、留白、修订规则）
        ↓
DiaryRepository ── RDB（日记记录）
SettingsRepository ── Preferences（设置）
        ↓
Reminder / Share / Backup 系统服务
```

建议目录：

```text
entry/src/main/ets/
├─ entryability/
├─ pages/
├─ components/
├─ model/
├─ viewmodel/
├─ service/
├─ repository/
├─ utils/
└─ constants/
```

## 7. 本地数据设计

`Preferences` 保存提醒、主题与首次引导等轻量设置；`RDB` 保存全部日记。直接使用 RDB 而不是单个 JSON 文件，便于后续按月份加载、生成长卷、统计、迁移和备份。

### daily_record

| 字段 | 类型/约束 | 说明 |
| --- | --- | --- |
| `local_date` | TEXT PRIMARY KEY | `YYYY-MM-DD`，提交时的本地日期 |
| `content` | TEXT | 1–4 个用户感知字符；留白时为空 |
| `note` | TEXT | 选填，最多 30 字 |
| `record_type` | TEXT | `WORD` 或 `BLANK` |
| `font_id` | TEXT | 定稿时字体，历史记录不受全局设置影响 |
| `paper_id` | TEXT | 定稿时纸张主题 |
| `submitted_at` | INTEGER | 首次提交时间戳 |
| `revised_at` | INTEGER NULL | 修订时间戳 |
| `revision_used` | INTEGER | 0 或 1，唯一修订规则依据 |
| `schema_version` | INTEGER | 未来数据库迁移预留 |

写入必须在 RDB 事务中完成：先校验本地日期、记录状态、修订次数、字数和注解长度，再插入或更新。缺失记录表示尚未记录；`BLANK` 不使用空字符串推断。

### 时间规则

23:59 的截止以设备本地时间为准。离线产品无法彻底阻止用户调整系统时间，因此它只能作为自我仪式规则，不能作为奖励、排行榜或防作弊依据。时区变化不应重开已有日期的修订机会。

## 8. 系统能力

- **提醒**：仅在用户主动开启后创建本地通知；权限拒绝或投递失败时，在设置页给出解释和跳转入口。
- **分享**：`ShareCardRenderer` 使用固定画布渲染图片，导出单日卡或 7 日长卷，不附带日记以外的分析数据。
- **备份**：1.0.x 以有版本号的 `.oneword` JSON 文件实现导出和导入。导入前预检记录数量、日期冲突和文件损坏；失败绝不覆盖现有数据。加密备份与隐私锁在同一后续版本完成。
- **桌面卡片**：1.1 实现。采用 FormExtensionAbility、卡片配置与卡片更新生命周期；每次写入后主动刷新，不依赖高频后台刷新。

## 9. 商业化

采用“免费核心 + ¥2 永久高级版”。不能把记录、历史查看、留白、提醒或基础备份等数据所有权能力收费。

| 免费 | 高级版（¥2，永久） |
| --- | --- |
| 记录、留白、修订、长卷 | 全部高级纸张、字体和分享版式 |
| 提醒与基础备份 | 高清月度/年度长卷导出 |
| 1 种基础分享卡 | 月度/年度视觉报告与高级卡片样式 |

付费触发时机为完成 7 条记录后首次使用高级字体或生成月度长卷时，禁止首次启动、首次提交和数据导出时弹付费墙。权益须本地保存，并支持 IAP 恢复购买。

## 11. AI 组诗边界（2.0）

AI 组诗定义为“可选的联网创作”，而非本地日记自动分析。用户主动选择时间范围和参与文字；生成前单独说明上传内容、服务商、是否留存与删除机制。服务端应最小化处理且不保存原始日记。输出必须标为“AI 创作”，不能伪装为心理理解或心理建议。离线时明确提示需要网络，不能静默使用模板诗冒充 AI。

若以上隐私承诺无法兑现，则只做本地年度字句排版，不使用“AI”命名。

## 12. 验收标准

- 从冷启动到完成一条记录不超过 3 次主要点击。
- 任意日期仅一条最终记录；修订机会不会因快速点击、重启或进程恢复而重复消耗或绕过。
- 覆盖 23:58 首次提交、23:59 修订、跨日打开、已写与留白互转、时区变化等情形。
- 按用户感知字符计数，正确处理 Emoji 和组合字符。
- 断网、通知权限拒绝、备份损坏、导入冲突时不崩溃，且反馈清晰。
- 深浅主题、不同屏幕密度与大字号下分享图和页面不截断。
- 屏幕朗读可读出日期、记录内容/留白及剩余修订次数。
- 不申请无关权限；不产生网络请求；字体、纸张和导出素材均有明确商用授权。
