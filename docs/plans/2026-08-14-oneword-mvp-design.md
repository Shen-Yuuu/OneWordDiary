# 一字日记：1.0 产品与技术方案

- 初稿：2026-08-14
- 最近更新：2026-08-17
- 状态：范围已确认，待开发
- 开发目录：`OneWord_dev/`

## 1. 产品定义

**一天一字，一年成诗。**

产品品牌为“**一字**”，中文商店名使用“**一字日记**”；英文品牌为“**OneWord**”，英文商店名使用“**OneWord Diary**”。

一字是一款离线优先的 HarmonyOS 原生日记工具。用户每天用 1–4 个字符留下当下，也可以正式选择留白。记录按时间沉淀为私人文字长卷，产品不使用连续打卡、社交比较或信息流占据注意力，而以留白、克制和回看积累建立习惯。

“一年成诗”是对长期积累的品牌表达，1.0 不自动生成诗歌，也不暗示 AI 会理解用户情绪。

目标用户是 18–35 岁、偏好极简生活并有审美表达需求的人。1.0 只支持手机，核心验证目标是：用户在第 7 天仍愿意打开并记录，并能从最近 7 日长卷中感受到积累价值。

## 2. 1.0 的产品原则

- 首发采用“一字仪式”路线，不做情绪轻日记、社交报告或压力型打卡。
- 数据默认只保存在本机；不登录、不云同步、不接统计 SDK、不发起网络请求。
- 不申请网络权限，不启用系统自动备份；备份只由用户主动导出和导入。
- 单日正文允许 1–4 个用户感知字符；可选一条不超过 30 个用户感知字符的注解。
- 留白是与写字平等的最终状态，不代表未完成或失败。
- 首次提交后，在首次提交时确定的当日截止时间前可以修订一次；修订确认后永久定稿。
- 唯一一次修订允许“已写 → 留白”和“留白 → 已写”。
- 历史正文、注解和记录类型不能删除或反复编辑；用户只能在设置中清空全部数据。
- AI 组诗、情绪标签、成就、统计、登录、云同步和 IAP 不进入 1.0。

## 3. 1.0 功能范围

### 包含

1. **今日记录**：日期、每日灵感、1–4 字输入、风格预览、可选注解、提交确认。
2. **今日留白**：用户可以确认“把今天留给空白”。
3. **一次修订**：提交后显示剩余一次机会和截止时间，修订后永久定稿。
4. **文字长卷**：按日期纵向浏览正文、留白和日期；点击查看单日详情。
5. **温和积累提示**：显示“已留下 N 天”，写字和留白都计入，不显示连续天数。
6. **本地提醒**：用户主动开启、选择时间，应用只创建本地通知。
7. **本地分享**：导出单日卡片或最近 7 日微型长卷，通过系统分享面板分发。
8. **基础备份**：导出和导入带版本号的 `.oneword` JSON 文件。
9. **基础设置**：两套完整风格预设、提醒、隐私说明、备份和清空全部数据。

### 明确不包含

登录、社区、云同步、情绪标签、成就、连续打卡、月度/年度统计、AI 组诗、隐私锁、桌面卡片、日历浏览、卡片流、多端适配、IAP 和高级版。

## 4. 信息架构

```text
今日（默认首页）
├─ 输入 / 留白 / 提交
├─ 当日完整卡片 / 一次修订
├─ 文字长卷
│  └─ 单日详情
├─ 分享预览
└─ 设置
   ├─ 风格
   ├─ 提醒
   ├─ 备份与恢复
   ├─ 隐私说明
   └─ 清空全部数据
```

首页是唯一主入口，不设底部导航。长卷和设置从首页右上角进入，应用每次冷启动都直接面对“今天”。页面导航使用 Stage 模型下的 `Navigation` / `NavDestination`，避免混用多套导航状态。

## 5. 今日记录流程

### 未记录状态

1. 显示日期与一行低对比度灵感；灵感来自本地文案，可换一条，不保存、不要求回应。
2. 用户输入后实时查看风格预览；“备注（可选）”始终显示在正文下方，与正文一起确认和保存。
3. 点击“落字”进入确认层；再次点击“收入长卷”才写入数据。
4. 提交成功后执行 180–300ms 的纸张/墨迹定格动效和轻触感反馈。
5. 遵循系统“减少动效”设置；减少动效开启时使用无位移、短渐变或直接完成。

留白使用同一确认层，确认文案为“把今天留给空白”。长卷中以淡圆圈表示留白，日期位置保持完整。

### 已提交、尚可修订

- 首页展示当日完整卡片和“今日尚可修订 1 次，至 23:59”。
- 点击修订后先展示原内容，并明确提示“本次确认后永久定稿”。
- 只有最终确认成功才消耗修订次数；取消、返回、进程被杀或写入失败都不消耗。
- 即使修订后的内容与原内容相同，只要用户最终确认成功，也视为已使用修订。

### 已定稿或超过截止时间

- 不再展示编辑入口。
- 仍可查看详情、分享和备份。

## 6. 字符与日期规则

### 用户感知字符

正文和注解都按 Unicode grapheme cluster 计数，不能使用字符串 UTF-16 长度直接判断。

- 正文保存前做 NFC 规范化并去除首尾空白。
- 正文允许 1–4 个 grapheme cluster，不允许纯空白或换行。
- 注解保存前做 NFC 规范化并去除首尾空白，最多 30 个 grapheme cluster，不允许换行；空内容保存为 `NULL`。
- Emoji、肤色修饰符、ZWJ 家庭 Emoji 和组合附加符应按用户看到的一个字符计数。
- 留白由 `record_type = BLANK` 明确表达，不能通过空字符串推断。

### 日期与修订截止

- 首次提交时生成 `local_date`，并按当时设备时区计算该日期结束时刻，保存为绝对时间戳 `revision_deadline_at`。
- 修订资格只由 `revision_used == 0` 且 `now <= revision_deadline_at` 决定，不根据当前时区重新计算。
- 时区变化不会重开已有记录的修订机会。
- 用户手动回拨系统时间无法在纯离线应用中彻底防止；该规则只服务于自我仪式，不用于奖励或防作弊。
- 旅行后如果当前 `local_date` 已存在记录，则展示该记录；如果是新的本地日期，则可以创建当天记录。
- 不允许补记过去日期，也不允许预先记录未来日期。

## 7. 视觉与内容

- 主视觉使用暖白纸张、墨灰文字和极淡朱砂色状态点。
- 1.0 提供两套完整风格预设，而不是字体和纸张自由组合：
  - `paper_ink`：暖白宣纸 + 稳重宋体/系统替代字体。
  - `plain_ash`：素白纸张 + 清简黑体/系统替代字体。
- 当前风格只影响新记录和输入预览；历史记录使用提交时保存的 `font_id`、`paper_id`，不随全局设置变化。
- 开发阶段使用可替换的占位字体、纹理、图标和本地灵感文案；公开发布前替换为有明确商用授权的素材。
- 注解只在单日详情中显示；分享图片默认不包含注解，避免无意泄露更私密的内容。
- 分享前必须展示完整预览。

## 8. 技术基线

现有工程位于 `OneWord_dev/`，采用以下基线：

- HarmonyOS Stage 模型与 `UIAbility`。
- ArkTS、ArkUI 声明式 UI。
- 手机设备类型。
- SDK：`6.0.1(21)`；`targetSdkVersion` 与 `compatibleSdkVersion` 当前均为 API 21。
- 单 `entry` 模块，不在 1.0 拆分 feature 模块。
- 严格类型，不使用 `any`、动态属性或依赖不安全类型断言。
- UI 状态使用不可变更新；复杂 UI 抽成可复用组件。
- 不引入网络、统计、登录、广告或远程配置依赖。

工作用应用标识：

- 品牌名：一字 / OneWord
- 商店名：一字日记 / OneWord Diary
- 开发期 `bundleName`：`com.oneword.diary`
- 版本：`1.0.0`

`bundleName` 在首次外部分发或上架前确认唯一性，发布后不再变更。

## 10. 本地数据设计

`Preferences` 保存当前风格、提醒配置、首次引导等轻量设置；RDB 保存全部日记。使用 RDB 是为了保证唯一约束、事务写入、分页长卷、迁移和安全导入。

### `daily_record`

| 字段 | 类型/约束 | 说明 |
| --- | --- | --- |
| `local_date` | TEXT PRIMARY KEY | 首次提交时的本地日期，`YYYY-MM-DD` |
| `content` | TEXT NULL | `WORD` 为 1–4 个 grapheme；`BLANK` 为 `NULL` |
| `note` | TEXT NULL | 选填，最多 30 个 grapheme |
| `record_type` | TEXT NOT NULL | `WORD` 或 `BLANK` |
| `font_id` | TEXT NOT NULL | 定稿时字体 |
| `paper_id` | TEXT NOT NULL | 定稿时纸张 |
| `submitted_at` | INTEGER NOT NULL | 首次提交 Unix 毫秒时间戳 |
| `submitted_tz_offset` | INTEGER NOT NULL | 首次提交时 UTC offset，单位分钟 |
| `revision_deadline_at` | INTEGER NOT NULL | 首次提交时固定的修订截止时间戳 |
| `revised_at` | INTEGER NULL | 修订成功时间戳 |
| `revision_used` | INTEGER NOT NULL | `0` 或 `1` |
| `schema_version` | INTEGER NOT NULL | 记录结构版本，初始为 `1` |

首次提交和修订必须使用 RDB 事务：读取当前状态、校验输入与修订资格、写入、再次读取确认。唯一主键和事务共同防止快速双击生成重复记录或多次消耗修订。

缺失记录表示尚未记录，不能与 `BLANK` 混淆。

## 11. 系统能力与隐私

### 提醒

- 仅在用户主动开启后请求通知权限并创建本地通知。
- 权限拒绝、通知被系统关闭或调度失败时，在设置页解释原因并提供系统设置入口。
- 修改时间、关闭提醒、重启设备和时区变化后，应重新核对下一次本地提醒。
- 提醒正文不包含日记内容。

### 分享

- `ShareCardRenderer` 使用固定逻辑画布渲染单日卡或最近 7 日微型长卷。
- 单日卡和 7 日长卷默认都不包含注解。
- 导出临时文件存放在应用缓存，分享完成或超时后清理。
- 分享内容只包含预览中可见的信息，不附加分析标识、用户标识或隐藏元数据。

### 基础备份

- 文件扩展名为 `.oneword`，内容是带 `format_version` 的 UTF-8 JSON。
- 文件包含日记记录和风格设置；不导入通知权限或设备相关提醒状态。
- 1.0 备份不加密，导出前明确提示“文件包含私人记录，请妥善保管”。
- 导入先完成格式版本、字段、字符长度、日期、记录数量和完整性预检，然后才开启事务。
- 日期冲突时保留本机记录，只导入缺失日期；不提供覆盖模式，完成后报告导入与跳过数量。
- 任意解析、校验或事务错误都不得改变现有数据。

### 系统备份

当前模板包含 `EntryBackupAbility` 且允许系统备份恢复。1.0 必须移除该扩展能力或明确关闭 `allowToBackupRestore`，保证数据不会在用户未主动操作时离开本机。

### 清空数据

设置页提供“清空全部数据”。操作需要两步确认，第二步明确说明无法恢复。清空日记和应用设置后取消已注册提醒，并回到首次使用状态。

## 12. 异常与恢复原则

- 写入按钮在事务进行中禁用，重复事件返回同一个结果，不重复写入。
- 应用切后台、进程被杀或系统重启后，以数据库状态恢复 UI，不依赖内存中的“已提交”标记。
- RDB 初始化或迁移失败时不继续写入，展示可理解的错误并保留原数据库。
- 备份损坏、导入冲突、通知拒绝、分享失败时都不能导致日记丢失。
- 页面不显示底层异常堆栈；日志不得输出正文和注解。

## 14. AI 组诗边界

AI 组诗只能是用户主动发起的联网创作。用户选择时间范围和参与文字，生成前单独说明上传内容、服务商、是否留存与删除机制。输出标记为“AI 创作”，不能伪装成心理理解或建议。

若无法兑现最小上传和不保存原始日记的承诺，则只做本地年度排版，不使用“AI”命名。

## 15. 1.0 验收标准

- 从冷启动到完成一条记录不超过 3 次主要点击。
- 任意 `local_date` 只有一条最终记录。
- 修订机会不会因快速点击、返回、重启、进程恢复或时区变化而重复获得或误消耗。
- 覆盖 23:58 首次提交、23:59 修订、跨日打开、写字与留白互转、时区变化和系统时间回拨提示。
- Grapheme 计数正确处理常见 Emoji、ZWJ、肤色修饰和组合字符。
- 365 条以上记录的长卷滚动流畅，按需加载，不一次性构建全部复杂组件。
- 断网、通知拒绝、备份损坏、导入冲突、分享失败时不崩溃且反馈清楚。
- 深浅系统模式、常见手机宽度、不同密度和大字号下，页面与分享图不截断。
- 屏幕朗读能读出日期、正文或留白、剩余修订次数和危险操作提示。
- 系统减少动效开启后不执行明显位移动效。
- 不申请无关权限、不产生网络请求、不启用系统自动备份。
- 日志、分享临时文件和错误信息不泄露日记内容。
- 发布素材均有明确商用授权。

## 16. MVP 验证方式

由于 1.0 不接统计 SDK，使用 10–20 名种子用户做 D1、D3、D7 轻量访谈，不要求用户上传日记内容。

重点只验证三件事：

1. 第 7 天是否仍愿意打开并记录。
2. 最近 7 日长卷是否让用户感受到积累价值。
3. 双确认、一次修订和留白规则是否造成不必要压力。

种子测试结束后再决定 1.1，不以功能数量作为 1.0 成功标准。
