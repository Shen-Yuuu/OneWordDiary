# 背景渲染与系统安全区修复设计

日期：2026-09-09。状态：用户已确认。

## 问题与结论

用户在另一套项目环境和真机上确认，纸色蒙版提高到 0.9、中心遮罩提高到 0.2 后，画面仍接近完整高饱和原图。按普通 alpha 合成计算，边缘纸色覆盖应为 0.9，中心应为 0.92，不可能只有轻微变化。因此问题不在参数强度，而在当前以两个空 `Row` 绘制纸色和渐变的合成路径没有稳定作用于真机最终画面。

修复不再继续提高空容器蒙版数值。`PaperBackdrop` 继续提供不透明主题纸色和纸纹，`DiaryBackground` 只保留已经确认能够显示的 `Image` 节点，并直接设置图片自身透明度。默认 `PHOTO_IMAGE_OPACITY` 为 0.16，最终视觉约由 84% 纸张和 16% 图片组成。该值越低，背景越淡、文字越清楚；以后只需修改一个常量。

## 组件设计

`DiaryBackground` 保留 URI 变化监听、加载代次、成功与失败回调、缺图回退和上下安全区扩展。删除 `scrimOpacity`、`fixedLightScrim`、纸色解析、透明纸色和阅读中心颜色，以及两个空 `Row`。图片成功解码前整个图片层保持不可见；成功后只显示低透明度图片，失败时继续露出 `PaperBackdrop`。首页、确认页、详情页和单日分享均复用同一常量，单日分享不再硬编码 0.74。

编辑页删除 76×52 背景缩略图。全页背景已经实时展示选中的图片，因此缩略图不再提供额外信息。无图时显示“选择背景”，有图时显示“更换背景”和“移除”；两个操作按钮使用至少 48vp 高度并提供完整无障碍名称，图片选择和删除业务逻辑不变。

## 系统栏与布局

`EntryAbility` 保留透明状态栏、透明导航栏和深色系统图标，但将 `setWindowLayoutFullScreen(true)` 改为 `false`。这样页面前景内容由系统自动避让状态栏和底部导航区域。`PaperBackdrop` 与 `DiaryBackground` 继续只扩展自己的上下系统安全区，使纸色或照片仍覆盖系统栏区域，交互内容本身不调用安全区扩展。

不使用固定顶部 padding。固定数值无法正确覆盖刘海、挖孔、横屏、手势导航和三键导航等不同设备形态。

## 验收

- 静态检查确认 `DiaryBackground` 只有一个图片透明度常量，不再存在 0.74、0.12、纸色蒙版 Row 或单日分享局部覆盖。
- 全量 Hypium 测试通过，背景图片的日期隔离、替换、移除、失败回退、分享等待和备份行为保持不变。
- Debug signed HAP 构建成功，记录唯一产物的绝对路径、大小、时间和 SHA-256。
- 真机分别临时使用 0.05 与默认 0.16 对照；画面必须出现显著强度差异，证明属性作用于实际图片节点。
- 真机检查首页和所有 NavDestination 的顶部内容不与系统栏重叠，底部按钮保持在导航安全区内，同时背景连续覆盖上下系统区域。
