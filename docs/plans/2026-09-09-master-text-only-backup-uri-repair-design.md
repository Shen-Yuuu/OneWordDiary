# master 分支纯文字备份与文档 URI 修复设计

## 目标

将“初始基础 APP 功能”分支已验证的备份文件读写修复同步到 master，同时明确备份边界：只导出和导入日记正文、备注及记录所需的文字元数据，不包含背景图片。

## 边界

- 保留 master 的本机背景图片字段、数据库迁移、图片服务和页面展示能力。
- 备份协议固定为 `format_version: 1`，单文件上限 5 MiB，最多 10000 条记录。
- 导出时忽略记录的 `backgroundImageId`，JSON 中不出现 `background_image` 或图片 Base64。
- 导入记录的 `backgroundImageId` 固定为 `null`；同日期本机记录继续跳过，因此原有本机背景不受影响。
- 含图片的历史 v2 备份明确返回“不支持的版本”，避免成功提示掩盖图片丢失。

## 文件读写

系统文件选择器返回的是文档 URI，不保证能作为应用沙箱路径使用。备份服务通过可注入的 `BackupFileGateway` 读写：

1. 使用 `openSync(uri, mode)` 获取文件描述符。
2. 使用 `statSync(fd)` 获取大小并在读取前执行上限校验。
3. 以循环处理部分读取和部分写入；写入使用 `WRITE_ONLY | TRUNC`。
4. 在 `finally` 中关闭文件描述符，并保留原始读写错误的优先级。
5. 编解码层再次按 UTF-8 字节数执行 5 MiB 校验，覆盖直接文本入口。

## 验收

- 文档 URI 的导出、覆盖导出和导入均只通过文件描述符路径。
- 含背景的本机日记导出后仍为 v1 纯文字文件。
- 导入新增日期不创建图片；冲突日期不覆盖正文、备注或背景。
- 损坏文件、v2 文件、超限文件和超过记录数上限均在写数据库前失败。
- 背景上传、展示、清理和数据库字段保持可用。
