# 一字日记：今日记录闭环设计

- 日期：2026-08-18
- 范围：实施节点 2，仅手机端“今日”页面
- 需求来源：产品方案与 `docs/design/oneword-ui-page-state-list.md`

## 方案

使用一个 `Index` 页面承载今日闭环，页面由 `TodayUiState` 驱动，并将输入、确认、已记录三类画面拆为独立 ArkUI 组件。`TodayViewModel` 持有草稿和页面状态，页面只转发用户意图，不直接访问 RDB 或拼装业务规则。

不把输入、确认、修订拆成多个路由页面：这些状态共享同一份临时草稿，多页面返回栈会增加误提交和恢复复杂度。也不把全部状态直接写进 `Index.ets`，避免状态分支与视觉代码耦合。

## 状态与数据流

启动时由 `EntryAbility` 完成本地服务初始化，`Index` 创建 ViewModel 后从 `DiaryService.getToday()` 恢复当天记录：

1. 无记录进入输入态。
2. 有记录且修订可用进入可修订展示态。
3. 已使用修订或超过固定截止时间进入永久定稿态。

正文、注解、留白选择和确认层都只是内存草稿。首次提交只有“收入长卷/确认留白”调用 `submit()`；修订只有“确认定稿”调用 `revise()`。成功后重新读取服务状态，失败返回原确认内容。取消、返回、切后台和进程结束都不会触发写入。

## 页面结构

- 顶部：本地日期、星期、长卷和设置占位入口；节点 2 不提前实现后续页面。
- 输入区：1–4 个用户感知字符、实时计数、灵感、始终可见的可选备注和近距离错误提示。
- 确认层：暖白覆盖层，展示本次正文或正式留白，提供最终确认与返回修改。
- 已记录卡片：展示当日正文/留白、可选注解、提交时风格、修订资格或已定稿状态。
- 修订：复用输入组件，回填原内容；允许写字与留白互转，最终确认前提示“确认后永久定稿”。

视觉沿用暖白、墨灰、克制朱砂和大面积留白。开发阶段使用系统 serif/sans-serif 字体；不从 HTML 引入网络字体、图标库或纹理请求。

## 错误与边界

- 输入错误在字段附近显示，主操作不可用。
- 保存期间禁用所有最终确认操作，进程内日期锁与 RDB 主键共同防重复。
- 修订保存失败明确提示“机会仍保留”；超时则重新加载为永久定稿。
- 初始化失败不展示日记内容，提供重试入口。
- 日志只记录状态事件，不包含正文或注解。

## 验证

- ViewModel 单测覆盖初始恢复、写字、留白、首次确认、取消、写字/留白互转、一次修订、过期与失败恢复。
- 本地 Hypium 测试通过后执行 Debug HAP 构建。
- 真机阶段补充输入法、焦点、屏幕朗读、大字号、减少动效和进程恢复验收。
